# Questions for another day

None of these has to be answered for the steps. They are listed so that nothing decided now closes them off.

- **Typed Data and config schema.** Portable Schema is meant to eventually succeed both as the way core describes data. That is a long way off, and until then both stay and are read as they are.
- **Field widgets.** Whether field widgets and the elements a generated form uses grow toward one shared contract.
- **HTTP.** How an API for operations relates to JSON:API and REST.
- **Recipes.** Whether config actions and recipe inputs read an operation's description.
- **Reading JSON Schema back into data definitions.** With both directions, a component's props, a Tool API tool's input and a config object go through the same code.
