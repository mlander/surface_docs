# Proposing a change

Decisions on this site have written reasons. A proposal to change one builds on those reasons instead of weighing the alternatives again from the start.

## What a proposal says

1. **The decision it revisits**, with a link to its record.
2. **What is new since then.** A case it did not consider, a change in core, a measurement, or a contributed module that does it another way.
3. **The facts that drove the decision.** Either the proposal keeps them, or it says why they no longer hold.
4. **The same test.** The change is tried on the same real cases as the original.

## Where it goes

Open an issue in the proof of concept's [issue queue](https://www.drupal.org/project/issues/surface) and name the talking point. If the proposal is accepted, the decision record gets a dated note, the page changes, and the talking point's level is set again.

Parts rated Working, Sketch or Question need no proposal: they are open to review and redesign as they are.
